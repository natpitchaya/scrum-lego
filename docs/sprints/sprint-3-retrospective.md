# Sprint 3 Retrospective

**Sprint:** 3
**Scrum Master:** Iris Yang

## Highlights
### What Went Well
*   **End-to-End Flow:** Completed a full flow delivering real value (Discovery -> Calendar).
*   **Collaboration:** Increased collaboration led to faster debugging cycles.
*   **Deployment:** Early deployment to Render prevented late-stage integration surprises.
*   **Data Insight:** Gained a clearer understanding of event-data variability.

### What Could Be Improved
*   **Estimation:** Data ingestion complexity was underestimated (format differences, missing fields).
*   **Architecture:** Scrapers need more modularization.
*   **Story Sizing:** Several stories were too large, slowing execution.
*   **Testing:** Coverage remains low.

## Gap Analysis
We missed the goal on filtering/metadata and user accounts because:
1.  Data ingestion took longer than expected.
2.  Frontend styling required additional iteration for stability.

## Action Items (Sprint 4 Preview)
To address the gaps and finalize the MVP, Sprint 4 will focus on:
*   **UI/UX:** Improved styling and Filtering UI.
*   **Backend:** Backend endpoints for filtering and a tagging system for categories.
*   **Features:** User login and preference saving.
*   **Ops:** Automated nightly scraping workflow.
*   **Docs:** Improved documentation and API comments.
