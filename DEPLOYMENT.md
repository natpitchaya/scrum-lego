# Deployment Guide for Yale Events Aggregator on Render

## Prerequisites
- GitHub repository pushed to GitHub
- Render account (free tier works fine)

## Step-by-Step Deployment

### 1. Prepare Your Repository
Make sure all changes are committed and pushed to GitHub:
```bash
git add .
git commit -m "Configure for Render deployment"
git push origin main
```

### 2. Create New Web Service on Render

1. Go to [Render Dashboard](https://dashboard.render.com/)
2. Click **"New +"** → **"Web Service"**
3. Connect your GitHub repository (`natpitchaya/scrum-lego`)
4. Select the branch you want to deploy (e.g., `trial1` or `main`)

### 3. Configure the Service

Render will auto-detect the `render.yaml` file, but verify these settings:

**Basic Settings:**
- **Name:** `yale-events-aggregator` (or your preferred name)
- **Region:** Choose closest to your users
- **Branch:** `trial1` or `main`
- **Runtime:** Python 3
- **Build Command:** `./build.sh`
- **Start Command:** `cd backend && gunicorn backend.wsgi:application --bind 0.0.0.0:$PORT`

**Environment Variables:**
The following are automatically set from `render.yaml`:
- `PYTHON_VERSION`: `3.12.0`
- `DEBUG`: `False`
- `SECRET_KEY`: (auto-generated)
- `ALLOWED_HOSTS`: Update this with your actual Render URL

### 4. Update ALLOWED_HOSTS

After Render assigns your URL (e.g., `yale-events-aggregator.onrender.com`):

1. Go to your service's **Environment** tab
2. Update the `ALLOWED_HOSTS` variable:
   ```
   your-service-name.onrender.com,localhost,127.0.0.1
   ```
3. Save and trigger a new deployment

### 5. Optional: Add PostgreSQL Database

For production, consider using PostgreSQL instead of SQLite:

1. In Render Dashboard, create a new PostgreSQL database
2. Link it to your web service
3. Render will automatically set the `DATABASE_URL` environment variable
4. Your app is already configured to use it (see `settings.py`)

### 6. Monitor Deployment

1. Watch the build logs in Render Dashboard
2. The build process will:
   - Install Python dependencies
   - Run Django migrations
   - Collect static files
   - Fetch events from Yale sources
3. Once deployed, visit your URL: `https://your-service-name.onrender.com`

## Maintenance

### Update Events
Events are automatically fetched during deployment. To manually update:

1. Use Render Shell or SSH into your service
2. Run: `python manage.py fetch_events`

### View Logs
- Go to Render Dashboard → Your Service → Logs
- Monitor errors and requests in real-time

## Troubleshooting

### Build Fails
- Check build logs for Python/dependency errors
- Ensure `requirements.txt` is up to date
- Verify `build.sh` has execute permissions

### 500 Internal Server Error
- Check `DEBUG` is set to `False`
- Verify `SECRET_KEY` is generated
- Check `ALLOWED_HOSTS` includes your Render URL
- Review application logs

### Static Files Not Loading
- Ensure `collectstatic` runs in `build.sh`
- Check `whitenoise` is in `requirements.txt`
- Verify `STATIC_ROOT` is configured

### Database Errors
- For SQLite: Limited to single instance
- For PostgreSQL: Check `DATABASE_URL` is set
- Run migrations: `python manage.py migrate`

## Performance Notes

- Free tier: Service spins down after 15 minutes of inactivity
- First request after idle period takes ~30 seconds
- Consider upgrading to paid tier for 24/7 availability
- SQLite works for read-heavy workloads but consider PostgreSQL for production

## Security Checklist

- ✅ `DEBUG = False` in production
- ✅ `SECRET_KEY` auto-generated by Render
- ✅ `ALLOWED_HOSTS` properly configured
- ✅ Static files served via WhiteNoise
- ✅ HTTPS enabled by default on Render
